# Development and Testing

## Code Generation

### Generating the SDK

The interface that this project provides, including what CLI commands are available and what configuration is required is defined in [`generate.yml`](https://github.com/Arm-Debug/go-sdk-generator/blob/main/generate.yml). From this file the Go SDK code is generated using the [Go SDK Generator](https://github.com/Arm-Debug/go-sdk-generator). Follow these steps to make changes to the interface.

#### Prerequisites

##### On Linux

On Debian based systems:

1. Make the dependencies available on the host:
 * `echo "deb [trusted=yes] http://$ARTIFACTORY_USER:$ARTIFACTORY_PASSWORD@localhost:80/artifactory/cmsis-tools bionic main" | sudo tee /etc/apt/sources.list.d/artifactory.list && echo "deb [trusted=yes] https://$ARTIFACTORY_USER:$ARTIFACTORY_PASSWORD@$ARTIFACTORY_HOST/artifactory/cmsis-tools bionic main" | sudo tee /etc/apt/sources.list.d/artifactory.list`
2. Run `sudo apt install go-sdk-generator`

On Red Hat based systems:

1. Make the dependencies available on the host:
    * Create a source file such as `/etc/yum.repos.d/fpga-artifactory.repo`
    * Add the following content:
    ```
    [ArmToolsArtifactory]
    name=Arm Tools Artifactory
    baseurl=https://artifactory.internal.tools.arm.com/artifactory/fpga-service-rpm
    enabled=1
    ```
2. Run `sudo yum install go-sdk-generator`

##### Other systems

- Install the SDK Generator from its release page.

#### Steps

1. Manually change the interface definition in [`generate.yml`](https://github.com/Arm-Debug/go-sdk-generator/blob/main/generate.yml).
2. Run the Go SDK Generator

```
go-sdk-generator generate -i generate.yml -o ./ -g 1.26.5
```

> :book: Note: The `-g` flag specifies the targeted Go version in semver format (e.g., `1.25.0`). Use the Go version from your project's `go.mod` file.

> :book: Note: Adding `--overwrite` will regenerate all the files including `go.mod` and files containing some state.

### Generating Mocks

The tests use [https://github.com/uber-go/mock](GoMock). Mocks are generated by `mockgen` for the interfaces defined in this project.

If you add a new interface file and want mocks to be generated for it you will need to add a comment to the file. This comment indicates that the command specified should run whenever `go generate ./...` is run at the top level of the go project. See [the Go documentation on generation](https://go.dev/blog/generate).

For example, to run mockgen, add this comment:
```
//go:generate go tool mockgen -destination=mocks/mock_$GOPACKAGE.go -package=mocks <package namespace>/$GOPACKAGE IMyInterface
```
This assumes the `go version` used is greater than 1.24.

You can then generate all mocks by running:
```
go generate ./...
```

## Release Types

The CI supports three release flows:

- `development` for snapshot releases
- `release` for stable releases
- `beta` for pre-releases


| Type        | Purpose              | Version Number Format                          | GitHub Release | News Files Deleted |
| ----------- | -------------------- | ---------------------------------------------- | :------------: | :----------------: |
| Release     | General Availability | `<minor>.<major>.<patch>`                      |      Yes       |        Yes         |
| Beta        | Integration Testing  | `<minor>.<major>.<patch>-beta.<commit number>` |      Yes       |         No         |
| Development | Development Testing  | `<minor>.<major>.<patch>-dev+<git hash>`       |       No       |         No         |

# Detecting secrets

So that no secrets are committed back to the repository, a combination of two tools are run in CI:

- [GitLeaks]() : Scans the git history for usual secrets (e.g. AWS keys, etc.)
- [detect-secrets](https://github.com/Yelp/detect-secrets): Scans only the current state of the repository for anything which can look like secrets (strings with high entropy)

For the latter, False positive keys are stored in the [baseline](./.secrets.baseline) which `detect-secrets` checks against when it runs

## Baseline & False positives

To flag individual false positives add comment `# pragma: allowlist secret` to line with secret

To add all suspected secrets in the repository (excluding ones with an allow secret comment), run `detect-secrets scan --all-files --exclude-files '.*go\.sum$' --exclude-files '.*\.html$' --exclude-files '.*\.properties$' --exclude-files 'ci.yml' --exclude-files '\.git' > .secrets.baseline`

If on Windows: then change the encoding of the .secrets.baseline file to UTF-8 then convert all `\` to `/` in the .secrets.baseline file
