Write a generator manifest

When to use this guide

Write a YAML or JSON manifest to define one coherent set of user-facing Go operations. The manifest controls the generated SDK surface, optional CLI, configuration, documentation, and supporting files. Domain-specific operation logic is implemented afterwards in Go.

Start from the contract

Use generator/schema/schema.yml for the complete field definitions, or print the schema as JSON with go-sdk-generator schema. The repository's generate.yml shows a real input. The key sections under specification are:

Field Purpose
package_name, main_module, name, description Project and SDK identity.
interface Public Go operations and their arguments and results.
global_configuration Values shared across the SDK and CLI.
command_line_commands Optional binary and commands exposing those operations.
additional_types Optional domain types used by the contract.

When operations accept functional options, use specification.options; see configure functional options for option wrappers, value_field and CLI bindings.

A minimal starting shape is:

specification:
  package_name: example-tool
  main_module: example
  name: Example
  description: Verify an example project.
  licence: Apache-2.0
  interface:
    notCloseable: true
    namespace: github.com/example/
    methods:
      - name: Verify
        description: Verify an example project.
        returns:
          - name: err
            lang_type: error
            description: Verification failure, if any.
  global_configuration: []

This describes a library surface. Add command_line_commands if users also need a CLI; see the repository manifest for commands, flags, and shared configuration. Adapt the namespace, name, operation, and licence to your project. What the generator produces explains the resulting project structure.

Model values deliberately

  • Use specific lang_type aliases such as duration, uuid, filepath, or service where they match the value. See types, formats and defaults for the complete built-in reference. Prefer reference: true, list: true, or iterator: true to encoding shapes into the type string; list and iterator cannot be combined.
  • Use enum for closed string choices, constraints for validation and relationships, and example or examples for representative values. These feed generated validation, help, documentation, and action inputs.
  • Keep truly shared values in global_configuration; put operation-specific values on that command. Mark credentials with secret: true and follow secret management in generated CLI tools for storage and loading behaviour.
  • Give operations verb names and write descriptions from a user's perspective. Avoid defining a transport endpoint as an entire operation if the intended action is a higher-level workflow.
  • For incompatible changes to a published contract, document a replacement with deprecation_notice before removing the old surface. Follow breaking changes and deprecation.

The manifest-authoring skill contains a detailed checklist for agents and maintainers.
